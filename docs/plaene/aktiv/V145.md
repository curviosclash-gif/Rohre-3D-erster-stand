# Plan-Autopilot fuer gate-sichere Subphasen-Automatisierung

Status: Abgeschlossen im Master-Index. Drift-Hinweis 2026-06-11: Der Live-Executor ist seit 2026-06-10 per Regel eingefroren (Report-only); `npm run autopilot:run` existiert nicht mehr. Details in der Drift-Notiz am Dateiende.

## Kurzfassung

V145 baut ein separates Automatisierungs-Tool, das normale Agentenarbeit nicht veraendert. Der Orchestrator waehlt deterministisch eine sichere Subphase, parkt `USER-GATE`-, D3- und D4-Scope, kann an anderer freier Stelle weitersuchen und startet Codex nur als Worker fuer genau einen freigegebenen Slice.

Der wichtige Schnitt bleibt:

- Der Orchestrator entscheidet deterministisch anhand von Master, Plan-Map, Locks, AI-Matrix und Git-Zustand.
- Codex fuehrt nur den exakt gerenderten Subphasen-Prompt aus.
- `USER-GATE`, D3 und D4 werden nie automatisch ausgefuehrt.
- Normale Codex-/Agent-Arbeit und bestehende Governance-Regeln bleiben unveraendert.

## Ziel

- Ein `plan-autopilot`-Tool fuer Dry-run, Auswahl, Gate-Parking und optionalen `codex exec`-Worker bauen.
- Bei geparktem Gate automatisch eine andere freie, zulaessige Subphase suchen.
- Auswahl und Stopps testbar machen, bevor ein echter Codex-Run erlaubt wird.
- Worker-Ausgaben maschinenlesbar machen, damit das Tool `completed`, `gate_required`, `blocked` und `no_change` unterscheiden kann.
- `auto-safe` als konservativen Default und `auto-d2-review` als spaeteren Nuetzlichkeitsmodus bereitstellen.

## Nicht-Ziel

- Keine Aenderung an `.agents/rules/`, `.agents/workflows/`, `AGENTS.md` oder normaler Agenten-Governance.
- Keine automatische Umsetzung von `USER-GATE`, D3 oder D4.
- Kein Auto-Revert, Auto-Stash, Auto-Clean, Force-Push oder History-Umbau.
- Kein `git add .` und keine Aufnahme fremder uncommitted Aenderungen.
- Kein paralleler Multi-Worker-Implementierungsmodus im MVP.
- Kein Source-of-Truth-Wechsel fuer Master, aktive Plaene, Generated-Indizes oder Locks.

## Betriebsmodell

| Modus | Verhalten |
| --- | --- |
| `dry-run` | Default: Snapshot bauen, Kandidaten sortieren, Gates parken, geplante Aktion ausgeben; keine Repo-Aenderung. |
| `auto-safe` | Nur `[AUTO]`, D0/D1 und harmlose D2-Reports auswaehlen; D2-`[REVIEW]` wird geparkt. |
| `auto-d2-review` | D2-`[REVIEW]` darf als Tool-Scope gestartet werden; `USER-GATE`, D3 und D4 bleiben geparkt. |
| `report-only` | Nur Kandidaten, Parking-Gruende, Readiness und Stopps ausgeben. |
| `run` | Live-Ausfuehrung mit `codex exec`; nur mit explizitem `--max-slices` und sauberem Scope. |

## Zustandsmaschine

```text
PRECHECK
  -> BUILD_SNAPSHOT
  -> SELECT_NEXT_CANDIDATE
  -> CLASSIFY_GATE
  -> PARK_OR_RUN
  -> CLAIM_LOCK
  -> RENDER_PROMPT
  -> CODEX_EXEC_ONE_SLICE
  -> VALIDATE_DIFF
  -> RUN_CHECKS
  -> COMMIT
  -> RELEASE_OR_ADVANCE_LOCK
  -> LOOP
```

Gate-Verhalten:

```text
Gate erkannt -> nicht claimen oder Lock freigeben -> parked_gate speichern -> naechsten Kandidaten suchen
```

Teilzustand nach Worker-Start:

```text
keine Aenderungen + gate_required -> parken, Lock freigeben, weiter suchen
Aenderungen vorhanden + gate_required/blocked -> stoppen, Partial Work nicht weiter automatisieren
```

## AI-Ausfuehrungsmatrix

| Arbeit | Decision | Gate |
| --- | --- | --- |
| Dry-run Planner, Parser, Kandidatenreport, Fake-Executor | D0/D2 | [AUTO] |
| `plan-autopilot.mjs`, Prompt, Worker-Output-Vertrag und Tests | D2 | [REVIEW] fuer Umsetzung, aber tool-lokal und ohne Governance-Default-Aenderung |

| Auto-Stage fremder Aenderungen, Auto-Revert, Auto-Stash, Auto-Clean, History-Operationen | D4 | [USER-GATE], im MVP Nicht-Ziel |
