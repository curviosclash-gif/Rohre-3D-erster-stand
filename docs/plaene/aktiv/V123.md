# AI-optimierter Plan-Index und Source-of-Truth-Migration

## Kurzfassung

Der bestehende `docs/Umsetzungsplan.md` ist fuer Menschen und Git gut lesbar, aber fuer AI-Agents und Scripts nur indirekt strukturiert. Tabellen muessen geparst werden, Sonderfaelle stecken in Freitext, und Agents lesen im Zweifel mehr Kontext als noetig.

V123 fuehrt deshalb einen maschinenlesbaren Plan-Index ein. Der Umbau erfolgt konservativ: zuerst als generierter, nicht-kanonischer JSON-Spiegel mit Drift-Check gegen den Master, spaeter optional als Source-of-Truth-Migration, bei der Markdown und HTML nur noch generierte Ansichten sind.

Ergaenzung 2026-05-24: Der Plan-Index soll die bestehende Arbeitsstrom-/Scope-Lane-Sicht als `workstream` maschinenlesbar machen. Diese Lane ist eine Navigations- und Filterdimension fuer Menschen, Plan Map und Agents; sie ersetzt nicht Blockstatus, Prioritaet, Dependencies, Locks oder Abschluss-Gates. Die V134-Intake-Lanes (`candidate`, `adopted-open`, `adopted-done`, `bot-training`, `meta`) bleiben davon getrennt.

## Ziel

- AI-Agents finden aktive, geplante und blockierte Bloecke ueber eindeutige Felder statt Markdown-Tabellen.
- `docs/Umsetzungsplan.md` bleibt in der Pilotphase kanonisch und menschlich lesbar.
- Ein Validator verhindert Drift zwischen Master und `docs/generated/plan-index.json`.
- Scope-/Workstream-Lanes werden strukturiert erfasst, ohne eine zweite Reihenfolge oder zweite Statusquelle einzufuehren.
- Erst nach stabilen Laeufen wird entschieden, ob der strukturierte Index die kanonische Quelle wird.
- Bestehende VXX-Detailplaene bleiben die Detail-Wahrheit pro Block.
- HTML bleibt optionales Dashboard, nicht AI-Quellformat.

## Nicht-Ziel

- Kein direkter Ersatz von `docs/Umsetzungsplan.md` durch HTML, LaTeX oder ein Dashboard.
- Kein zweites vollstaendiges Plansystem neben Master, VXX-Dateien und Changelog.
- Keine automatische Status-, Phasen- oder Lock-Aenderung ohne User-Gate.
- Keine Planverschiebung, Archivierung oder Graph-RAG-Implementierung als Nebenwirkung.
- Kein Umbau produktiver Spiel-, UI-, Recording-, Multiplayer- oder Bot-Training-Pfade.

## Ausgangslage

- `docs/Umsetzungsplan.md` ist aktuell der kompakte Master-Index.
- Kanonische Details liegen in `docs/plaene/aktiv/VXX.md`.
- V116 reduziert bereits den Standard-Lesekontext und klassifiziert Planrauschen.
- V119 soll historische Abschluss- und Evidence-Drift klaeren.
- V120 baut auf klaren Quellen und Evidence-Paketen fuer Graph-RAG auf.
- `V121` ist bereits als Graph-RAG-Viewer-Draft reserviert; dieser Plan nutzt deshalb `V123`.

Format-Regel:

- Der MVP nutzt JSON statt YAML, damit Node-Scripts ohne neue Parser-Dependency validieren koennen.
- `docs/generated/plan-index.json` wird generiert und nicht manuell gepflegt.
- Falls spaeter menscheneditierbare strukturierte Planung gewuenscht wird, braucht das ein eigenes User-Gate fuer YAML/Dependency/Autoritaet.

MVP-Sonderfaelle:

- `depends_on: "-"` wird im JSON zu `[]`; mehrere Dependencies bleiben als Reihenfolge aus dem Master erhalten.
- Freie Owner und freie Locks bleiben als Master-Werte sichtbar (`owner: "frei"`, `lock.status: "frei"`), ohne daraus Scheduling abzuleiten.
- Abgeschlossene, aber noch referenzierte Bloecke bleiben normale `blocks` mit `status: "done"` und ihrer Master-Gruppe; Archiventscheidungen gehoeren nicht in den Index.
- Fehlende oder geschlossene Locks werden nur als kompakte Projektion aus der Master-Lock-Tabelle gespiegelt; Schreibabsicht muss weiterhin `docs/lock-status/*.json` und Lock-Tooling pruefen.

Start-Regel:

- `start_anchor` beschreibt den aktuellen Master-Anker.
- `next_recommended_start` beschreibt die naechste Empfehlung.
- Beide Felder duerfen keine automatische Scheduling-, Lock- oder Statusentscheidung ausloesen.

Workstream-Regel:

- Jeder Block bekommt genau einen primaeren `workstream`.
- `workstream` dient fuer Navigation, Filterung und AI-Kontextwahl.
- Querliegende Dependencies bleiben ausschliesslich ueber `depends_on` sichtbar.
- Mehrfach-Tags oder sekundare Lanes koennen spaeter additiv folgen, gehoeren aber nicht zum MVP.
- In der Pilotphase bleibt der Master-Arbeitsstrom-Index die Workstream-Wahrheit; der JSON-Index spiegelt ihn.
- Plan-Map-Workstream-Mappings duerfen mittelfristig nicht als unabhaengige dritte Wahrheit weiterlaufen: sie muessen gegen den Master-/Index-Stand validiert oder aus derselben Quelle gespeist werden.

Lock-Regel:

- Der JSON-Index enthaelt pro Block eine generierte kompakte Lock-Projektion.
- Lock-Autoritaet bleibt in der Pilotphase beim bestehenden Lock-Wahrheitsraum und der Master-Lock-Sicht.
- Agents duerfen Lock-Daten aus dem Index als Einstiegshilfe nutzen, muessen bei Schreibabsicht aber die kanonische Lock-/Master-Sicht beachten.

Nicht im MVP-Schema:

- Lange Evidence-Texte
- Vollstaendige Phasenlisten aus VXX-Dateien
- Changelog-Historie
- Vollstaendige Graph-Kanten
- Mehrfach-Lanes, Sprintplanung oder Kanban-Status
- Auto-Archivierungsentscheidungen

## Risiken

| Risiko | Stufe | Gegenmassnahme |
| --- | --- | --- |
| Zwei Wahrheiten zwischen Markdown und JSON | hoch | Pilot bleibt generierter Spiegel; Drift-Check gegen Master ist Pflicht; Konflikt gewinnt Master |
| Generator erzeugt falsch wirkende Plaene | hoch | Generator erst nach Validator-Stabilisierung; keine Source-of-Truth-Drehung in Phase 1 |
| Schema wird zu eng und zwingt Sonderfaelle in Freitext | mittel | MVP nur fuer Master-Index-Felder; VXX-Details bleiben Markdown |
| Schema wird zu breit und wird ein zweites Plansystem | mittel | Keine Evidence-, Changelog- oder Vollphasenmodellierung im MVP |
| Bestehende Tools lesen weiter Markdown | mittel | Fallback-Pfade behalten; Tools erst optional an `docs/generated/plan-index.json` anbinden |
| Agents lesen Markdown plus JSON plus Reports | mittel | Leseweg klar regeln: JSON fuer Index, genau eine VXX-Datei fuer Details |
| Workstream wird faelschlich als Prioritaet oder Reihenfolge interpretiert | mittel | `workstream` ausdruecklich nur als Navigationsfeld behandeln; `prio`, `depends_on`, `current_phase` und Lock-Status bleiben entscheidend |
| Bestehende Plan-Map-Intake-Lanes werden mit Scope-Lanes vermischt | mittel | Feldnamen trennen: `workstream` fuer Master-Bloecke, `intakeLane` fuer Draft-/Intake-Status |
| Strukturierte Felder verleiten zu mechanischen Statusupdates | hoch | D3/D4-Gates bleiben; Status-/Phase-/Lock-Aenderungen nie automatisch |
| Plan-Map-, Master- und Index-Workstreams laufen auseinander | hoch | Master-Arbeitsstrom bleibt Pilot-Wahrheit; Validator prueft Index/Plan-Map-Mapping gegen Master |
| Lock-Projektion wird als Lock-Wahrheit missverstanden | mittel | Index-Lock nur Einstiegshilfe; Schreibpfade pruefen kanonische Lock-/Master-Quelle |
| JSON wird manuell editiert und driftet vom Generator weg | mittel | Datei unter `docs/generated/`; Header/Check markiert sie als generiert; manuelle Aenderungen gelten als Drift |

AI-Benachrichtigungsregel:

- Sobald `123.1` bis `123.4` abgeschlossen sind oder ein Agent anhand vorhandener Evidence erkennt, dass `123.5` entscheidungsreif ist, muss der Agent stoppen und den User aktiv benachrichtigen.
- Die Benachrichtigung muss knapp nennen: Option A `Markdown bleibt Wahrheit, JSON bleibt generierter Spiegel`, Option B `JSON wird Wahrheit, Markdown wird generierte Menschenansicht`, vorhandene Evidence, fehlende Evidence, Restrisiko und Empfehlung.
- Ohne diese User-Entscheidung duerfen keine Source-of-Truth-Aenderung, keine generierte Master-Markierung und kein Anschlussplan als angenommen umgesetzt werden.
