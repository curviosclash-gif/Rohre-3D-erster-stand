# Fehlerbericht: V89 89.99.1 Kernscope-Gate durch `node-contract`-Restfehler blockiert

## Kontext

- Block: `V89 Desktop-first Testarchitektur und Desktop-Verifikation`
- Subphase: `89.99.1`
- Ziel: Den dokumentierten Kernscope aus `node-contract`, `desktop-smoke` und den zugehoerigen Skript-/Gate-Einstiegen mit den neuen V89-Namen als blockerfrei oder blockerfest belegen.
- Laufzeit: 2026-04-12 (Europe/Berlin)

## Fehlerbild

- `npm run test:desktop:smoke` ist gruen und bestaetigt den minimalen Desktop-Hauptpfad ueber die echte Electron-Shell.
- `npm run test:contract` ist nicht gruen: 68 Tests passieren, genau ein Contract-Test faellt.
- Der aktuelle Restblocker sitzt in `tests/training-environment.contract.test.mjs` bei `T97: WebSocketTrainerBridge erfasst Retry/Timeout/Fallback-Telemetrie deterministisch`.
- Die Assertion auf `requestTick` erwartet `3`, bekommt im aktuellen Lauf aber `1`; dadurch ist der `node-contract`-Layer fuer den Kernscope nicht blockerfrei.

## Reproduktion

1. `npm run test:contract`
   - Ergebnis: `68 pass / 1 fail`
   - Fail: `tests/training-environment.contract.test.mjs:347`
   - Assertion: `assert.equal(Number(action?.requestTick || 0), 3)` -> `1 !== 3`
2. `npm run test:desktop:smoke`
   - Ergebnis: `2 passed`
   - Specs: `tests/core.spec.js` prueft Desktop-Boot bis Menu/Preload-Bridge sowie Matchstart/Input/Return-to-Menu erfolgreich.

## Betroffene Komponenten

- `tests/training-environment.contract.test.mjs`
- `src/entities/ai/training/WebSocketTrainerBridge.js`
- `package.json` (`test:contract`, `test:desktop:smoke`, `test:core`)

## Bereits versucht

- Kernscope mit den V89-Einstiegen direkt neu ausgefuehrt, statt nur die V88-Blockerdoku weiterzuverwenden.
- `node-contract` und `desktop-smoke` getrennt verifiziert, damit der Desktop-Smoke-Status trotz Contract-Restfehler belastbar sichtbar bleibt.
- Keine fachliche Aenderung am Training-/Bridge-Vertrag in `89.99.1`, um den Scope nicht in Richtung Folgefix oder `89.99.2` auszuweiten.

## Status

- `89.99.1` ist fuer den Kernscope blockerfest dokumentiert.
- `desktop-smoke` ist blockerfrei.
- `node-contract` und damit auch der guenstige Sammel-Einstieg `npm run test:core` bleiben durch `T97` blockiert, bis der Trainings-/Bridge-Vertrag wieder deterministisch gruen laeuft.

## Naechster Schritt

- Den Restfehler `T97` im Training-/Bridge-Vertrag ausserhalb von `89.99.1` fachlich klaeren oder einem passenden Folgeblock zuordnen.
- Danach `npm run test:contract` und `npm run test:desktop:smoke` erneut ausfuehren, um den Kernscope voll blockerfrei zu machen.
